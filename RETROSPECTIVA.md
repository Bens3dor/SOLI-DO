1. ¿Qué funcionó bien?
Compromiso y colaboración del equipo:Todos los integrantes trabajaron de manera responsable y cumplieron con las tareas y roles asignados.
Uso de GitHub como herramienta CASE: La organización de las tareas mediante Issues y el tablero Kanban nos permitió tener claridad sobre qué debía hacer cada quién y dar seguimiento al avance.
División del trabajo:Hubo buena disposición para dividirse equitativamente las actividades (redacción del README, creación de Issues, modelado y código).

 2. ¿Qué no funcionó / qué nos costó trabajo?
Gestión del tiempo y coordinación de horarios: Fue el reto principal. Debido a compromisos personales, laborales y del hogar de cada integrante, se nos complicó coincidir en tiempo real para reunirnos a trabajar juntos.
Curva de aprendizaje inicial: Al ser nuestra primera vez utilizando herramientas como Git, GitHub Projects y la sintaxis de Markdown, nos tomó tiempo entender la dinámica de trabajo y el flujo de comandos.
Comunicación asíncrona: Al no tener horarios coincidentes, la comunicación se volvió más lenta al esperar respuestas en los chats del equipo.

 3. ¿Qué haríamos distinto la próxima vez?
Establecer un cronograma y fechas límite internas: Definir entregas parciales desde el primer día para evitar acumular el trabajo hacia el final de la entrega.
Mejorar la comunicación asíncrona: Utilizar notas más detalladas en las tareas (Issues) de GitHub para que cualquier integrante sepa exactamente qué falta por hacer sin depender de reuniones presenciales o síncronas.
*Planificar sesiones de trabajo breves y enfocadas: Agendar pequeñas reuniones virtuales fijas de 15 minutos para revisar el tablero y resolver bloqueos de manera rápida.
